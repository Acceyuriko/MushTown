# 统一 Z 值 — 2026-10-25

## 0. 一句话

「谁盖谁」现在由三段互不相干的手写顺序决定（树里的加法顺序 / 面板的 `_topPanel` + 15 条两两比较 / 窗口 `List` 的先后 / `DrawHud` 里七段手写画序）。这份计划把它们收成**一个 int Z**：画和命中共用同一份序。

## 1. 现在怎么排的（代码事实）

| 地方 | 现在的规则 | 位置 |
|---|---|---|
| 场景内的树 | 加法顺序画，**倒序**命中（后加的盖前面） | `Core/Scene.cs` `TreeDraw.DrawObject` / `Scene.Hit` |
| HUD 的 8 个根 | 手写加法顺序：家具→exp→plate→bars→qslot→12 格→任务条→buff→boss→快捷菜单 | `HudBar.BuildGameScene` |
| 旧面板 6 个 | 画：`_topPanel` 最后、其余按 0..5 写死；点：`PanelsFrontToBack` 先试 `_topPanel` 再 0..5；重叠时 15 条两两 `if` 判谁赢 | `HudBar` `DrawHud` / `PanelsFrontToBack` / `UpdateHudClick` |
| 新窗口 | 画和点都按 `UiWindow.List` 的顺序；点一下就 `Raise`（挪到表尾） | `Panels/UiWindows.cs` |
| 最后几段 | `DrawHud` 手写：balloon → 树 → 面板 → 窗口 → 对话 → 手拿道具 → tips | `HudBar.DrawHud` |
| Esc | 先关最上面的窗口（`List.Last`），再关最上面的面板（`FrontPanel`） | `UiWindows.EscCloseFront` |

已经因为这个踩过的坑：

- HoverTip 一开始跟着对象在树里画，被后加的血条、快捷格键帽盖住（现在靠「最后统一画」硬补）。
- 点被压住的窗口不会置顶（`interaction-2026-10-24.md` 的 P0）。
- 面板重叠时，命中靠 15 条两两比较算出来，注释还要求「这个顺序必须和 DrawHud 一致」——两份手抄数据。
- 加一个窗口要同时改 `DrawWindows` / `ClickWindows` / `HoverWindows` / `EscCloseFront` / `Raise` / `Pinned` 六处。

## 2. 目标模型

1. **`GameObject.Z`（int，默认 0）**：只对场景根有效——Z 大的后画、先命中；Z 相同就按原来的加法顺序（现有树一行不用改）。子节点上的 Z 不生效。改根 Z 必须走 `Scene.Move`。
2. **一个场景**：`_gameScene` 和面板的 7 个 `_xxxScene` 全部取消，合成一个 UI 场景的根列表。（`UiWindow` 上保留一个指向这个场景的引用，只为拖标题时读同一个 `LastClick`，见 §8。）
   - 根列表按 (Z, 加法序) 排；`Draw` 正序、`Hit` 倒序，**两个方向共用一份序**。
   - `Hover` / `Click` 各一次调用就够，不再有「先问窗口再问面板再问 HUD」的链。
3. **面板和窗口各持有一个 host 根**：`GameObject Host`，Z 挂在 host 上。内容重建（`BuildInvScene` / `Build()`）只换 host 的孩子，host 本身和它的 Z 不变。拖动只是改孩子坐标，host 不动。
4. **Z 分带**（层与层之间留空，层内再排）：

   | band | 装什么 |
   |---|---|
   | -10 | 说话气泡（现在是 `DrawHud` 最先画的那段） |
   | 0–99 | HUD 常驻：家具、exp、plate、bars、qslot、12 格、任务条、buff、boss |
   | 100–199 | HUD 悬浮：快捷菜单 9 格 |
   | 200–299 | 旧面板：背包 / 属性 / 技能 / 任务 / 选项 / 商店 |
   | 300–399 | 窗口（含钉住的聊天框、小地图）：键位 / MENU / GUIDE / 大地图 / 组队 / 邀请弹窗 |
   | 500–599 | 对话（模态） |
   | 600 | 手拿道具 |
   | 700 | tips（文字 tip + 道具 tip） |

   钉住的窗（聊天、小地图）只是**不参与提升**：它们的 Z 停在 band 开头，所以永远在其他窗口下面、在面板上面——和现在一致。

5. **层内排名**：一行就是顺序。面板一行 `_panelOrder`（6 个 host），窗口一行 `UiWindow.List`；点一下置顶 = 把 host 挪到行尾，再 `band + 0..n-1` 重编号。不另写 `ZRank`：行只有两处，且钉住的窗（聊天、小地图）要特殊处理，抽出来反而绕。
6. **Esc**：面板取行里最后一个可见的，窗口取列表最后一个「可关」的，关它。`_topPanel` 不再需要。

## 3. 要删的东西

- `HudBar`：`_topPanel`、`PanelsFrontToBack()`、`UpdateHudClick` 里 15 条两两比较和 `z(int)`、`UpdateHudHover` 的三段链、`DrawHud` 里 6 段面板分支和 `DrawWindows()` 调用、`_invScene`/`_statScene`/`_skillScene`/`_questScene`/`_settingsScene`/`_shopScene`/`_talkScene` 七个字段。
- `UiWindows`：`DrawWindows()`、`ClickWindows()`、`HoverWindows()`、`OpenWindows()`；`Raise()` 不再动 Z 以外的绘制顺序，只挪行尾。窗口加 `Host` 根，`UiWindow.Scene` 保留（只为读统一的 `LastClick`）。
- `UiWindow.StartDrag` 里对静态 `LastClick` 的依赖改读合成场景的 `LastClick`（窗口持一个场景引用）。
- 各面板 `Build*Scene()` 里的 `_xxxScene = new Scene();` 换成 `Host.Clear()`。

实际 +286 / −273（净增 13 行）：合并顺序省下的代码，被 host 化和同步点摊平了。

## 4. 分四步做（每步都能编译、都能截图验收）

**第 1 步：Z 机制（不改行为）**
- `GameObject.Z`；`Scene` 根列表按 (Z, 加法序) 排序（Z 变了才重排，不是每帧排）；`Draw` 正序、`Hit` 倒序。
- 此时所有 Z = 0，画出来必须和现在逐像素一致（拿现有 `--shot` 图对比）。
- 门禁 + 截图对比。

**第 2 步：六面板并进来**
- 六个 `_xxxScene` 变 host 根（Z = 200 + 行号），`_showXxx` 保留布尔，`SyncPanels` 把布尔同步到 `host.Enabled`。
- 删 `PanelsFrontToBack` / `_topPanel` / `FrontPanel`（留给 Esc） / 15 条两两比较；点击、热键、MENU 开面板都走 `RaisePanel(id)`。
- 验收：面板互相重叠时点谁谁上浮；遮挡处点击不会漏到下面的面板；拖动、页签照旧。

**第 3 步：窗口并进来**
- `UiWindow` 加 `Host`；`Build()` 写 `Host.Clear()` + 重建孩子。
- 删 `DrawWindows` / `ClickWindows` / `HoverWindows` / `OpenWindows`；Z = 300 + 列表下标（`SyncWindowZ`），钉住的窗排在最前、其余按列表；点击先置顶再进按钮（按钮可能开新窗）。
- 验收：多窗叠放时点击/悬停/拖动都对；聊天和小地图永远在面板之上、Esc 关不掉。

**第 4 步：对话、手拿、tip 变成根对象**
- `_talkScene` 的根挂 band 500 并设 `Modal`；手拿道具一个根（600）；tips 走 `DrawTips` 改成根（700），或保持现在「最后画」但 Z 也占位（二选一，优先根对象，`DrawTips` 那套特判才能删）。
- 删 `DrawHud` 里剩下的手写顺序，`DrawHud` = 气泡根 + `Ui.Draw`。
- 验收：tip 永远在最上面（含压住键帽、血条、手拿道具、对话）；对话时点窗外无效。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| hover 音重复（现在按场景逐个 `SfxOnHover`，`HoverWindows` 特意不清 `_hoverId`） | 合成一次 `Hover` 后天然只响一次；合完再跑「停在 MENU 钮 3 秒数次数」那个老验法 |
| 删除逐场景 `ClearHover` 后残留高亮 | `Scene.Hover` 每帧重设唯一的 `Hovered`，不再需要逐场景清 |
| 模态（对话）失效 | `Modal` 标记本来就在 `Scene.Hit` 里全局判，合并后更简单；补一次「对话中点窗外无效」手测 |
| 面板拖动时坐标写死 | 面板现在就是绝对坐标 + 重建，host 化后只是换挂载点，坐标逻辑不动 |
| 面板重建丢失 Z | Z 在 host 上，host 不重建 |
| 排序每帧分配 | Z 只在变化时重排；根数量 < 30 |
| 截图全变 | 第 1 步就要求逐像素不变；后面每步都比对受影响的屏 |

## 8. 落地记录

四步全做了。实际做法：

1. **面板是一行**：`_panelOrder` 存 6 个 host 的后→前顺序，Z = `200 + 行号`。点击、热键、MENU 行、打开商店/属性都走 `RaisePanel(id)`：把 host 挪到行尾再重赋 Z。`_topPanel` 和旧的「前层 206 + 其余按 id」两档规则删掉；Esc 取行里最后一个可见面板。
2. **窗口的 Z 由 `UiWindow.List` 的次序算出来**（`300 + index`），`Raise` 还是挪表尾。这样 Esc 不用另写一份顺序。
3. **同步点在画之前**：`Draw` 里 `Begin` 之前跑一次 `SyncLayers()`（面板 + 窗口）。点击、Esc、网络推送、换图、死亡改过的层都在同一帧画之前落地，不用在每个改动点手写同步。`UpdateHud` 里另有一次，在 hover 之后、点击之前（点击要用本帧的 Rect；hover 与旧版一样滞后一帧）。

实际分带：气泡 -10；HUD 0（快捷菜单 100）；面板 200–205；窗口 300 起；对话 500；手拿 600；tips 700。聊天和小地图是「不参与 Raise」的窗口，所以永远停在窗口带最下面（2026-10-26 改成和面板同一行后，它们在行首、面板下面，见 §9）。

验证：14 张 `--shot` 图（hud/inv/stat/skill/quest/settings/shop/talk/minimap/worldmap/keys/menu/guide/party）与改动前逐字节一致；临时自检（已删）验过根节点 Z 有序、点谁谁上浮（连点三个面板的顺序）、窗口压在面板上、模态吞点击、会重建自己那一层的按钮（背包 +/-）点完仍上浮；`--aiticks` 跑过 Update 不崩；format / build / 296 测试全绿。

## 9. 2026-10-26 补：面板和窗口并成一行

用户报 bug：底部快捷行打开的面板，有的点了能到最前，有的不能；「打开 map 和 skill，skill 永远在 map 后面」。

原因：§8 留了两行（面板 200、窗口 300）。Z 小的那一行永远压不过窗口，所以面板不可能盖住 map。点击面板只改面板行，改不动窗口。

改法：

1. 两行并成一行 `_raiseRow`（`HudBar.cs`）：聊天、小地图钉在行首，然后 6 个面板，然后其余窗口；Z = `200 + 行号`。`RaiseHost` = 挪到行尾 + 重编号。构造函数建行（窗口先建好），`SyncLayers` 每帧重编号。
2. 点击抬升看 `TopAt` 命中物的主人：是窗口就 `Raise(w)`，是面板就 `RaisePanel(id)`。两者共用一行，所以面板能盖住窗口。
3. Esc 从行尾往前找第一个可关的（钉住的跳过），不再比 `Host.Z`。
4. 快捷行图标 `. 状态切换`（`HudQuickMenu.cs` 的 `QuickFeature`）：没开 → 在最前打开；开着但不在最前 → 只抬到最前；已经在最前 → 关闭。
5. 删掉 `SyncWindowZ` / `_panelOrder` / `WindowZ` / 无用的 `FrontPanel`。

验证：14 张 `--shot` 与 `logs\zbase` 逐字节一致；临时自检 9 条全过（面板盖过 map、点面板抬升、图标三态各一条、Esc 顺序）；format / build / 296 测试全绿；`--aiticks` 冒烟正常。
## 10. 2026-10-26 补：窗口点击不抬升

现象：点 map 面板，map 不动；点 skill 面板，skill 会到最前。

原因：每个窗口的整块背景 `Rect` 挂在窗口内容的**子节点**上（每个 Build 都是 `root.Add(new Rect(Rect()))`），命中的是子节点。`WindowOf` 只拿命中的对象和 `w.Host` 比，子节点比不中，于是返回 null，抬升分支不执行。面板用的是 `PanelOf`，它先 `RootOf`，所以面板一直是对的。

改法：`WindowOf` 先 `RootOf(o)` 再比 `w.Host`（`UiWindows.cs`）。窗口自己的整块 `Rect` 已经存在，不用另加。

验证：自检 6 条（skill 先到 map 上面、点 map 把 map 抬到 skill 上面、被盖住的面板不吃点击、点空处抬面板、聊天钉住不升）全过；14 张截图不变；296 测试全绿。

约定（用户 2026-10-26 明确）：HUD 底部只放 HP/MP/经验条和小地图；凡是由按钮打开的，都是能拖动、能改 Z 的活动窗口。面板和窗口已经同属一行，拖动各自都有标题条。
## 11. 2026-10-26 补：Character Info 和 Equip 是同一个窗口

快捷行的两个图标（Character Info、Equip）其实是同一个属性窗的两页。原来只按「面板是否在最前」判断，所以打开 Character 再点 Equip 会把窗口关掉。

改法（`HudQuickMenu.cs` 的 `QuickFeature`）：面板 id 1 且当前页不是要打开的那页时，走 `OpenFeature`（换页并抬到最前），不关闭。页已经对了才按三态处理：在最前就关，在后面就抬。

验证：自检 7 条全过（换页不关、留在最前、同页再点才关、在后面换页并抬升）；14 张截图逐字节不变；296 测试全绿。
