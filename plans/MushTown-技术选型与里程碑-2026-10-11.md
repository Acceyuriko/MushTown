# MushTown — MapleStory 复刻：技术选型与里程碑

日期：2026-10-11
状态：选型与架构已定稿（16 个逐项追问后）；W1、W2、W3 已完成，当前在 W4 之前
目标：局域网内复刻 MapleStory（冒险岛），自玩 + 朋友联机；主干优先，叶子后补
数据来源：本机客户端 `E:\游戏\maplestory`（WZ 资源）

---

## 1. 已定决策（含理由）

| # | 决策 | 选定 | 核心理由 |
|---|------|------|----------|
| 1 | 客户端形态 | .NET 桌面端 | WZ 解析器（最难部分）已有现成 C# 实现且实测可编译；浏览器会拦 Ctrl+W/Ctrl+T/F5 等快捷键；WebGL 不省任何难活 |
| 2 | 渲染框架 | MonoGame 3.8.6（DesktopGL/OpenGL） | 只做标准件（窗口/输入/图集/批处理/音效），游戏逻辑 100% 自写；MonoGame 稳定版只有 OpenGL 后端，Vulkan/DX12 仍是实验；2D 场景 API 老旧不是瓶颈。3.8.6 是当前稳定版，版本在 csproj 里写死不用通配符 |
| 3 | WZ 消费 | 只导用到的 → PNG + JSON | 数据共 65.33 GB / 1065 文件（Sound 8.2G、Skill 15.2G、Mob 13.7G），无法整体导出；导出一次后彻底免疫游戏更新导致的加密变化 |
| 4 | 素材分发 | 导出产物进 .gitignore | Nexon 版权素材进 public 仓库有 DMCA 下架风险；仓库只放导出工具 + 资源清单 + 文档 |
| 5 | 导出格式 | PNG（无损+透明）+ JSON | JPEG 无透明通道且有损块状；PNG 预计几十~几百 MB 可接受；以后要压再说 DDS/BC3（即 WZ 原生格式） |
| 6 | 服务端 | C# 控制台→实为类库，客户端托管 | 与客户端同语言同解决方案，共享协议与数据模型，无 JSON 契约维护 |
| 7 | 架构 | 从第一天 client-server | 移动/刷新/战斗本质是世界状态；迟些加网需要对客户端推倒重写；角色数据天然属服务端 |
| 8 | 部署形态 | 单 exe，主菜单【本机开房/加入主机】 | 星露谷/Terraria 式 listen server；进程内后台线程起服务端，无黑框；房主退出即世界消失（可接受） |
| 9 | 权威模型 | 移动客户端权威 + 游戏状态服务端权威 | 服务端拥有怪物/AI/HP/掉落/背包/任务；客户端本地算自己物理，服务端软校验（速度/边界/距离）；客户端永不跑怪物 AI |
| 10 | 日志 | 滚动文件为主（单文件 2MB×10 个），游戏内鼠标点击面板，全局异常钩子 | 无控制台，文件是崩溃诊断唯一渠道 |
| 11 | 内容范围 v1 | 冒险家战士线（新手→剑客→圣骑士→英雄）+ 彩虹岛 + 维多利亚港 + 2 张练级图 | 近战无弹道，技能形态仍全覆盖；四职业齐上会让纸娃娃工作量 ×4 |
| 12 | 纸娃娃 | 引擎按槽位通用写（加槽位不改格式），v1 只导新手套 | 通用循环（列表驱动 + 全过滤器），加槽位不改格式；装备系统放到 M9 |
| 13 | 物理碰撞 | foothold 线段模型 | 原版仅 foothold（无瓦片碰撞无墙）；单向平台+下坠+爬梯；线段插值顺带支持斜坡；VRect 钳边界 |
| 14 | 地图编辑器 | 不写 | 复刻目标用不到；导出 JSON 人可读可手改，自制地图是远期扩展 |
| 15 | 账号存储 | 单 JSON 文件 + 临时文件改名原子写 + PBKDF2 哈希 + 3 角色栏 | 局域网十几个字段，SQLite 的建表/迁移是纯负担；明文传密码可接受（LAN 威胁模型） |
| 16 | 技能/怪物 | SkillId 手工注册表（行为手写）+ Mob JSON 数值驱动；AI 少量原型 | 通用配置语言会越写越大；v1 战士线约 20-30 个技能 |
| 17 | 伤害公式 | 近似公式，单文件分步纯函数 + 全局倍率 | 原版公式服务端不公开；输入（攻防/技能倍率/怪物防御）全部 WZ 保真；参考 bwiki 公式页，以后改一个文件 |
| 18 | WzComparerR2 | git 子模块引入 | MIT 协议；锁 commit 可拉上游修复，必要时可 fork |
| 20 | 传输层 | TCP + NoDelay + 4 字节定长头二进制消息 | 原版 MapleStory 协议即 TCP（GMS v83：登录 8484/TCP，移动包也走 TCP）；"游戏用 UDP"是 FPS 类的结论（60-128Hz、单局多人才需要）；LAN 下 TCP 零负担，队头阻塞重传约 1 RTT(<10ms)，且白送有序/不丢/断线检测 |
| 19 | IDE | VS Code + C# 扩展 + dotnet CLI | .NET 8 SDK 8.0.416 已装；MonoGame 模板 `dotnet new install MonoGame.Templates.CSharp` |

## 2. 解决方案结构

```
MushTown.sln
├─ MushTown.Shared     协议消息、数据模型（无依赖）
├─ MushTown.Server     类库：账号、世界、怪物、战斗、存档（无 Console、无 UI）
├─ MushTown.Client     MonoGame exe：窗口/渲染/输入；开房时后台线程托管 Server
└─ MushTown.Exporter   命令行工具：WZ → PNG+JSON（开发期运行）
```

网络：`TcpClient.NoDelay = true`，4 字节定长头 + 二进制消息体（不套 HTTP/JSON）。同屏实体 = 全图广播（无视野裁剪，LAN 规模足够）。协议层放 Shared，客户端与服务端直接共享消息类型。UDP 留作未来可选项（传输层与消息层分离，要换只动传输层一个类；且即使换 UDP，也应先做"服务端 20-30Hz 快照 + 客户端插值"，与协议无关）。参考 [GMS v83 协议规范](https://raw.githubusercontent.com/nmnsnv/maplestory-wasm/master/docs/ms-network-protocol.md)（原版 TCP，登录 8484）。

## 3. 数据流

```
E:\游戏\maplestory\appdata\Data (WZ, 65GB)
   │  MushTown.Exporter（子模块 WzComparerR2.WzLib 解析 + 清单控制范围）
   ▼
assets/  ← 本地目录，.gitignore
   ├─ maps/{mapId}.json（坐标已烘焙成左上角）＋ assets/tiles/、assets/obj/、assets/back/ 三目录放贴图 png
   ├─ chara/body/{action}.json ＋ chara/body/{action}/{帧号}_{imgId}_{部件}.png（骨骼烘焙成坐标 + 帧图层）
   ├─ mob/{id}.json + png、skill/{id}.json + png、item/{id}.json + png（后续周新增）
   └─ manifest.json（来源客户端版本 + 导出日期 + 清单，后续周补）
   │
   ├─► MushTown.Client  本地加载（MonoGame Texture2D.FromStream，无 MGCB/XNB）
   └─► MushTown.Server  读取数值（怪物/技能/职业基础属性），运行时不需要贴图
```

服务端只吃 JSON 数值；贴图仅客户端用。

## 4. 关键机制研究结论（读 WzComparerR2 源码所得）

纸娃娃（`WzComparerR2.Avatar/AvatarCanvas.cs`）：
- 角色 = **骨骼树**。部件图片节点带 `z`（图层名或整数）与 `map`（骨骼名→偏移，链式）。
- 部件跨部件绑定靠**同名骨骼**（武器挂身体 hand 骨骼，身体动武器跟动）。
- 图层排序表 = `Base\zmap.img`；整数 z 换算 `zIndex<0 → ZMap.Count - zIndex`。
- 身体基座 = `Character\00002000.img`（罗列全部动作）；动作分级：基础动作 / 部件扩展动作 / 引用动作（action+frame 指向别的动作）。
- 每帧属性：delay、move、flip、rotate、face（表情）。耳朵类型、HairCover、WeaponIndex 过滤图层（CreateBone 的 switch，约 40 行规则）。
- 脸与身体各自独立帧号计时（CreateFrame(bodyFrame, faceFrame, ...)）。
- **结论：导出必须保留骨骼**，拍平每帧一张图会让换装备时位置全错。

地图（`WzComparerR2.MapRender/MapData.cs`）：
- 一张图 = `info`(VRLeft/VRTop/VRRight/VRBottom、bgm、link、town、fly、swim、returnMap、hideMinimap、fieldLimit) + `back`(rx/ry 视差、isFront) + 层 0~7（obj/tile，tile 带 tS 集名）+ `foothold`(7 层级，线段 x1,y1,x2,y2) + `life`(type, x, y, fh, mobtime, flip) + `reactor` + `portal` + `ladderRope` + miniMap + particle/light/effect。
- life 节点自带刷怪点坐标与所挂 foothold。

## 5. 里程碑

### M0 冒烟（整条管线打通）
- git init；MushTown.sln 四项目；VS Code 环境跑通；MonoGame 窗口。
- WzComparerR2 以子模块引入，引用 WzComparerR2.WzLib.csproj。
- 冒烟测试：WzLib 打开本机 KMST 新加密数据，打印 Base.wz / Character\00002000.img / Map 的节点树。
- Exporter 导出 1 张图 + 1 套角色外观到 PNG+JSON。
- **验收**：窗口里真正画出地图贴图 + 角色第一帧。

### M1 纸娃娃
- 导出 body/hair/face/weapon 全部基础动作；JSON 含骨骼+帧图层。
- 运行时：动画播放（delay/move/flip/rotate）、图层合成（zmap 顺序）、18 槽位引擎（内容仅新手套）。
- 固定键位表 v1（方向键/Alt 跳/下+跳 下坠/爬梯/Ctrl 攻击/Z 拾取/IKPQ 窗口），重绑定以后再议；键位一个都不占日志面板。
- **验收**：客户端场景中角色站/走/跳/表情/朝向全部正确，图层不错。

### M2 地图 + 服务端骨架
- 导出 5-8 张目标地图；运行时加载（视差、tile/obj/foothold/portal/life/ladderRope、小地图）。
- Server：TCP、连接、玩家进出图广播、地图实例、位置同步、VRect/速度软校验。
- Client：地图场景渲染、portal 换图（↑）、单向平台/下坠/爬梯、切图 loading。
- **验收**：两个客户端连本机服务端互相可见跑动；各自换图不掉线。

### M3 账号 + 存档 + 大厅
- 注册/登录（PBKDF2）、3 角色栏、host/join 菜单、日志面板+滚动文件、全局异常钩子。
- accounts.json（原子写）：角色等级/属性/装备/技能/任务/位置。
- **验收**：注册→建角色→退出→重登，数据不丢。

### M4 ★可玩主线：普攻战斗 + 经验 + 属性点
- 普攻挥砍（服务端判定）、伤害公式 v1（分步纯函数+倍率）、怪物从 life 刷点生成、HP/死亡/经验/升级、自动属性点（按职业比）。
- 药水/消耗品、怪物掉血/死亡动画、EXP 数字。
- **验收**：从 1 级打到约 10 级、加点、补给、被怪打死——完整循环可玩。

### M5 技能系统
- 注册表 + 约 20-30 个战士技能行为类、技能窗口、特效、SP 加点、冷却/耗蓝。
- **验收**：3 转前每个技能都能放且效果正确。

### M6 怪物系统完善
- AI 原型（被动/追击/飞行）、怪物攻击玩家、掉落物/拾取、刷新计时、广播。
- **验收**：怪物会主动打人、掉落可捡、定时重生、多人同时刷一致。

### M7 任务系统
- 导出现成官方任务（彩虹岛链）+ 自定义任务 JSON、任务窗口/追踪/奖励。
- **验收**：新建角色按任务链引导从 0 走到 10 级。

### M8 Boss
- 蘑菇王类：召唤小怪+冲撞循环、掉落、重生。
- **验收**：2~3 人组队可击杀，掉落正确。

### M9 UI 打磨 + 背包/装备
- 背包、穿装备（外观+数值真生效）、小地图、NPC 对话、基本商店。
- **验收**：换武器公共外观与攻击同时变。

### M10 扩展
- 其他职业线、联盟、小屋、组队、宠物/坐骑、更多地图与 Boss。

**原则**：M4 之前只做主干；M4 后可反复游玩；M5+ 每项都是独立叶子，随时可插入/跳过。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| WzLib 打不开这套 2026 新加密格式 | M0 第一件事冒烟测试；打不通就 patch WzLib 或 fork 子模块（MIT） |
| scope creep（内容太多） | v1 锁战士线+8 张图；新增内容=加导出清单再跑导出器，引擎不动 |
| public 仓库 DMCA | 素材 gitignore；仓库=工具+文档 |
| MonoGame OpenGL 限制 | 目前无被挡功能；真有具体需求再评 DesktopVK/DX12 |
| 伤害手感 | 全局倍率单点调参；bwiki 公式页做参考（见链接） |
| 后期加装备/职业导致数据格式改 | 18 槽位引擎一次写全；导出格式版本化（manifest.json） |

## 7. 立即动手（M0 顺序）

1. `git init` + .gitignore（assets/、data/、logs/、bin/obj）+ 子模块引入 WzComparerR2。
2. 建解决方案四项目；引用 WzLib；Client 装 MonoGame 3.8.6 DesktopGL（不用 MGCB 内容管线，贴图直接 `Texture2D.FromStream` 读 png）。
3. 冒烟：WzLib 打开 `E:\游戏\maplestory\appdata\Data`，打印节点树计数。
4. Exporter：Base\zmap.img + Character\00002000.img（stand 动作）+ Map/Map1/100000000.img → PNG+JSON。
5. Client：窗口 + 加载导出的第一张贴图与角色第一帧。
